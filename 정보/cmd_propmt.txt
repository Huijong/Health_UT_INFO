### 1. [데이터베이스 & 백엔드] 통합 포인트 트랜잭션 시스템 구축

* **신규 컬렉션 생성:** `points_transactions`
  * **스키마 구조:**
    ```json
    {
      "tester_name": "김민건",
      "points": 1,        // 정수형 (가감치: +5, -3 등)
      "memo": "자동 적립 (이메일 수집)" 또는 "관리자 가산 (우수 활동 보너스)",
      "month": "2026-07", // 월별 랭킹 정산용 (YYYY-MM)
      "created_at": "YYYY-MM-DD HH:MM:SS"
    }
    ```
* **동작 트리거:**
  * **자동 적립:** 이메일 파서가 새 수집 정보를 `verification_emails`에 인서트할 때, 해당 테스터(`tester_name`) 명의로 `points: 1`, `memo: "자동 적립 (이메일 수집)"`, `month: 당월` 정보를 `points_transactions` 컬렉션에 동시에 자동 등록하도록 백엔드 로직에 연동해 줘.
* **신규 API 추가:**
  1. `POST /api/points` : 관리자가 수동으로 특정 테스터에게 포인트 가감(points, memo, month)을 등록하는 API
  2. `GET /api/points/{tester_name}/history` : 특정 테스터의 모든 포인트 내역(시간순)을 가져오는 API
* **랭킹 API(`GET /api/rankings`) 계산 기준 변경:**
  * 기존 `verification_emails` 목록의 단순 개수를 세던 방식에서 ➡️ **`points_transactions` 컬렉션에서 해당 월(`month`)에 쌓인 `points` 합산(Sum) 기준**으로 랭킹 정렬 및 등수를 집계하도록 Aggregation 파이프라인을 수정해 줘. (1포인트 = 1점 기준)

    * 팝업 창 중앙에 **`[ - ]  현재 선택점수  [ + ]` 형태의 클릭 카운터 UI**를 배치하여 버튼 터치만으로 1점씩 손쉽게 올리거나 내릴 수 있도록 구현해 줘.

# [요구사항] 착용 스트랩 선택 카드 분리 및 유도 문구 개선 (온보딩 및 설정 공통)

## 1. 개요 및 배경
현재 스트랩 리스트는 하나의 리스트 카드로 보여지고 있습니다. 사용자들이 "1안"인 기본 스트랩 및 직접입력을 위주로 선택하도록 유도하기 위해 스트랩 리스트를 2개의 카드로 분류하고 유도 타이틀을 개선합니다.

## 2. 세부 구현 사항

### A. 공통 에셋 옵션 수정 (home_screen.dart)
- `kStrapOptions` 리스트 맨 앞에 `{'name': '기본 스트랩', 'url': ''}`을 추가합니다.

### B. 온보딩 스트랩 선택 화면 수정 (home_screen.dart - _buildStep3Strap)
1. **타이틀 변경:** 
   - 기존의 "테스트 시 부착한 공식/서드파트 스트랩 디자인을 고르세요." 문구를 **"1안(추천), 2안 중 테스트 시 부착한 스트랩을 고르세요."**로 변경합니다.
2. **카드 구조 이원화:**
   - **1안 카드 (GlassCard):** 
     - 제목: `"1안 (기본 스트랩/직접 입력)"` (우측에 추천 표시 배지 적용)
     - 내용: `기본 스트랩`, `직접입력` 두 개의 옵션만 노출.
   - **2안 카드 (GlassCard):** 
     - 제목: `"2안 (공식/서드파티 스트랩)"`
     - 내용: `기본 스트랩`과 `직접입력`을 제외한 모든 공식 스트랩 옵션을 노출.
3. **상태 공유:** 
   - 두 카드의 라디오 버튼은 하나의 `_selectedStrap` 변수를 공유하여 서로 배타적으로 선택되게 처리.
   - `직접입력` 선택 시 텍스트 입력 폼은 첫 번째 카드 하단에 부드럽게 나타나도록 연동.

개발 환경 : HealthPort 앱에 설정 > 실험실 진입시 워치에서 파일 가져오기 GUI 구현
주요 목표 : 워치에서 생성된 대용량 운동데이터 파일(.zip)을 스마트폰으로 빠르고 끊김 없이 전송하는 커스텀 연동 기능 구현

1단계:앱 원걱 설치 자동화(설치 프리 패스)
1. 사용자가 HealthPort앱 실험실 페이지에 진입 후 "워치에서 파일 가져오기" 카드를 누르게 되면, 블루투스 연결을 통해 워치에 전용 앱이 설치되어 있는지 확인합니다.
2. 앱이 없다면, HealthPort 앱에서 RemoteIntent API를 호출하여 워치의 구글 Play 스토어를 강제로 작동시키고, 내가 만든 워치 앱의 다운로드 페이지로 바로 이동시킵니다.(테스트 시에는 구글 플레이 콘솔의 "내부 테스트" 트랙 이용)

2단계:오프라인 1:1 기기 연결 및 파일 목록 요청
1. 두 기기가 연결되면 HealthPort 앱이 구글 Nearby Connections API(P2P_POINT_TO_POINT 전략)를 기동합니다.
2. HealthPort 앱에서 **GET_FILE_LIST**라는 가벼운 텍스트(BYTS) 명령을 전송합니다.
3. 워치 앱은 화면이 꺼져도 꺼지지 않도록 Foreground Service를 동작시키며, 수신한 명령에 반응하여 /sdcard/Download/ 폴더를 스캔합니다.
4. 워치에 쌓인 날짜별 운동 데이터 압축 파일 목록을 JSON 문자열로 변환하여 HealthPort 앱에 응답합니다.

3단계: HealthPort 앱에서 서낵 다운로드 및 초고속 전송
1. HealthPort 엡은 수신한 JSON 데디터를 해석하여 날짜별 파일 목록을 깔끔한 UI로 화면에 보여준다.
2. 유저가 HealthPort 엡에서 다운로드 할 파일을 선택하면, HealthPort앱이 워치 DOWNLOAD_FILE:[파일명] 명령을 전송합니다.
3. 명령을 받은 워치는 해당 파일을 로드하여 파일(FILE) 페이로드로 전송하고, 블루투스에서 자동으로 전환된 고속 무선 LAN(Wi-Fi Direct)망ㅇ르 통해 100mMB 파일을 10~20초에 완변 전송합니다.

우선 1단계를 하려면 워치 앱을 먼저 만들고 Play 스토어에 올려야 하는데 apk만 먼저 만들고 무선디거깅을 통해서 워치에 apk를 설치하고, HealthPort의 실험실 페이지를 통해 테스트를 할꺼야!
