1단계: dev 브랜치에서 일상적인 개발 및 푸시

# (혹시 다른 브랜치에 있었다면) dev 브랜치로 이동
git checkout dev

# 코드를 열심히 수정하고 기능을 구현합니다... (예: index.html 수정)

# 변경 사항 저장하기
git add .
git commit -m "feat: 로그인 기능 구현 완료"

# GitHub dev 브랜치로 푸시
git push


2단계: 최종 배포를 위해 main 브랜치로 합치기 (Merge)

# 1. 배포용 main 브랜치로 이동
git checkout main

# 2. 혹시 그사이 main에 다른 수정사항이 반영되었을지 모르니 최신화
git pull origin main

여기에서 방법 A

# 3. dev 브랜치의 변경 내용을 main으로 병합
git merge dev

# 4. 합쳐진 최종 main 상태를 GitHub에 업로드 (배포)
git push origin main

S

방법 A
dev 브랜치에서 기능 구현과 테스트가 모두 끝나서, 이제 실제 서비스용인 main 브랜치에 합칠 차례입니다.

💡 방법 A: GitHub 웹사이트에서 안전하게 합치기 (강력 추천)
실무에서는 주로 이 방식을 씁니다. 동료들의 리뷰를 거칠 수 있고 충돌을 시각적으로 확인하기 좋습니다.

GitHub 저장소 페이지에 접속합니다.

[Pull requests] 탭으로 이동해 [New pull request]를 누릅니다.

base: main ⬅️ compare: dev 로 설정합니다. (dev를 main으로 합치겠다는 의미)

변경 사항을 확인하고 [Create pull request]를 생성합니다.

문제가 없다면 [Merge pull request]를 눌러 최종 병합합니다.
